# Claude 구현 인계 — V3 P0~P3

Random-TD의 V3를 이어서 구현해줘. 사용자 결정은 [growth-plan.md](growth-plan.md)와 아래 조건을 기준으로 한다. 다시 선택지를 나열하거나 동일 결정을 확인받으며 멈추지 말고, 단계별로 구현·검증해줘.

## 시작점

- 저장소: `qkqh6898-woohak/Random-TD`.
- 기획·디자인·시범 에셋 브랜치: **`docs/v3-growth-revision`**, PR **#83**. 최신 원격 상태를 확인하고 해당 브랜치의 변경을 작업 기준에 포함해줘. 이미 다른 변경이 main에 들어갔다면 보존하고 충돌을 해결해줘.
- 저장소 `CLAUDE.md`, `docs/PROGRESS.md`를 먼저 읽고 역할·결정성·데이터·검증 규칙을 지켜줘.
- 기준 문서: `docs/v3/growth-plan.md`, `docs/v3/ui-contract.md`.
- Codex는 시범6장 생성·투명 WebP 후처리·크기별 정적 검토·화면 적용 계약을 완료했어. 총6크레딧 사용, 추가 생성0건. 결과는 `docs/art/higgsfield/v3-pilot/README.md`와 `jobs.json`, 파일은 `public/assets/v3/pilot/`에 있어. 실제 런타임 UI는 아직 구현되지 않았어.
- 이 브랜치는 게임 코드·저장 형식·SIM_VERSION·앱 버전을 바꾸지 않았어. 이미지6개를 기존 캐릭터159장 manifest에 섞지 않았어.

## 확정 방향

1. **P0→P1→P2→P3 우선**. P4 정령, 보물 제단, 초월Lv16~20, 난이도 확장은 후속이야.
2. 기존 **공격력+4%/Lv와 특색 보간을 유지**하고 마일스톤을 추가해. 기존 카드·재화·레벨·해방·기록을 회수하거나 적을 강화해 상쇄하지 마. 65종×Lv1~15와 지원·제어·경제 능력을 각각 비교해줘.
3. 신규 도장·패스·보급은 날짜 대신 유효 전투와 완료 웨이브로 진행해. 하루5개 제한·연속 출석 초기화는 없어. 기존 일일 퀘스트는 보존해.
4. 유물은24종 설계 중 첫12종만 공개해. 10회 천장·5:1 지정 교환·목표 조각·첫 유물 선택권을 제공하고, 이번 신규 재화는 탐험 열쇠1개만 노출해.
5. 표준10웨이브 완료 전투3~5판의 성장 선택·주력 유물50~70유효 전투는 **검증 목표**야. 카드와 불꽃 병목, 강화 골드까지 포함한 무료 트랙 수급표를 P0에서 산출해. 미확정 후보값을 검증 완료값으로 쓰지 마.
6. 전투·소환·배치가 중심이고 경제는 보조야. 기존 이자·도박·일꾼 값을 깎지 말고 신규 경제 유물의 상한·후보값으로 조정해줘.
7. 기존 통통한 그림체와 디자인 시스템을 유지해. 정령은 동물형 외형 시범2종만 준비됐고 이번 게임 화면에는 노출하지 마. 추가 이미지 생성·플랜 변경·과금은 이 인계 범위에 없어.

## 구현 순서

- **P0**: 기존 계정/전투 기준값, 효과 합성·상한·비용 JSON 스키마, 유효 전투·완료 웨이브·단일 지급 장부 사양과 수급표를 먼저 확정해. 지연·반복 정산은 runId로 중복 방지하고, 누락 필드는 기본값으로 읽어. 저장 백업을 되돌리는 모든 오프라인 조작까지 막는다고 주장하지 마.
- **P1**: Lv3/6/9/12/15 마일스톤. 기존 효과에 추가하고 이미 달성한 계정은 소급 인정. 영웅별 특색·공속 상한 때문에 무효가 되는 보상이 없는지 확인해. sim 변경 때만 버전을 올려.
- **P2**: 첫12유물, 열쇠·조각·천장·교환·목표 지정, 판 입력/리플레이 스냅샷과 진열장. 보급 후보 지급은 P2 정산과 P3 상자에서 중복 지급하지 않도록 같은 장부를 사용해.
- **P3**: 탐험 도장28유효 전투, 진행도 패스50칸, 긴 판에 비례하는 보급, 성장 선택·꾸러미·첫 영웅 선택권·비밀 코드. 기존 계정도 선택권과 이미 충족한 꾸러미 해금을 인정해. 황금 트랙은 선택형이며 핵심 성장의 유일한 재료 공급처가 되면 안 돼.

## 검증·보고

- 각 단계는 개별 구현 브랜치/PR로 나누고 `npm test`, `npm run check`, `npm run build`, 관련/전체 E2E를 저장소 규칙대로 수행해. 단계별 `docs/PROGRESS.md`에 변경·검증·제한을 기록해.
- 경계: 완료9/10/27/80웨이브, 잔여7+13, 도장27→28, 패스49→50, 날짜 변경, 동일runId 재정산, 기존 저장 예시, 미보유/만렙·천장·교환을 확인해.
- Codex 환경에서는 테스트123파일·1,753통과/5건너뜀, check·build가 통과했어. smoke E2E는 Chromium socket 권한 제한으로 화면 진입 전에 종료됐으므로 네 환경에서 다시 검증해줘. 실패 검사를 통과로 보고하지 마.
- 현재 실제 봇이 없는 수치를 통과했다고 쓰지 말고, 필요한 headless 비교를 만들어 성장 속도와 경제형/전투형 유물을 측정해줘.
- P0~P3 구현은 사용자에게 승인된 우선 범위야. main 병합·릴리스는 저장소의 해당 승인 규칙을 따르고, 승인 대기 전까지 가능한 구현·테스트·PR 준비를 모두 완료해줘.

최종 보고는 단계별 PR, 기존 계정 약화 여부, 무료 트랙 성장 속도 산출, 검증 결과와 남은 결정만 간단히 정리해줘.
