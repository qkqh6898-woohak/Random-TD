> 코드 기준: main `c13d9b27de7cc46f4afd51b2fc2b326d19d56d23`, v0.1.22.

## 1. 확정한 방향 7가지

| 항목 | 채택 방향 |
| --- | --- |
| 이번 범위 | **P0~P3**를 순서대로 구현·검증. P4~P6는 후속 |
| 성장 속도 | 표준 10웨이브 완료 전투 **3~5판마다 눈에 보이는 성장 선택**. 주력 유물은 표준 플레이에서 **1~2주** 목표 |
| 게임 중심 | **전투·소환·배치 중심**, 경제는 보조. 돈을 모으는 한 가지 조합이 모든 전투 조합을 대체하지 않게 |
| 유물 | 전체24종을 설계하고 **첫 공개12종**. 무작위+천장+지정 교환 |
| 보상 기준 | 새 출석·패스·보급은 **날짜 대신 전투 진행도**. 매일 접속 의무·연속 출석 초기화·하루5개 제한 없음 |
| 정령 외형 | **동물처럼 귀여운 꼬마 정령**. P4 구현은 보류, 시범2종으로 외형만 검토 |
| 그림 | 기존 통통한 그림체 유지. **시범6장 견적을 먼저 제시**하고 생성은 그다음. 전체 이미지 예산 상한120크레딧 |

추가 원칙:
- 기존 계정의 레벨·공격력·특색·보유 재화·카드·해방 상태·기록을 약화시키거나 회수하지 않는다.

- 기존 특색 보간을 제거하거나 Lv6까지 지연하지 않는다. 새 마일스톤은 기존 효과에 추가한다.
- 실제 돈·광고·입장 에너지는 추가하지 않는다. 보석도 플레이로 획득한다.
- 재화는 최종 최대4개 추가를 상한으로 두고, **P0~P3에는 탐험 열쇠1개만** 노출한다.
- Codex는 화면·아이콘·연출 디자인, Claude는 로직·저장·밸런스·통합. 구현 요청 없이 역할을 이유로 작업을 확대하지 않는다.
- 현재 연결은 push 권한이 확인됐다. “읽기 전용이라 재연결 필요” 문구는 삭제한다.

개별 단계 완료 후 플레이 확인을 거친다. P1~P3을 한 번에 묶어 게임에 투입하지 않는다.

## 4. 기존 계정 약화 방지

### 4.1 영웅별 기준 보존

- 같은 영웅·계정Lv·판 입력·배치·시드에서 기존 기본 공격력, 공속, 사거리, 치명타, 제어 지속, 발동 확률이 낮아지지 않는다.
- “전체 평균 DPS가 같음”으로 일부 영웅의 하향을 가리지 않는다. 65종 각각을 확인한다.
- 회복·지원·경제 영웅은 DPS 외에 MP/지원량·코인·제어 시간을 별도로 비교한다.
- 새 영웅을 키워야 예전 수준을 회복하는 방식, 기존 특색을 Lv6/12에 다시 잠그는 방식은 사용하지 않는다.
- 게임 난도를 올려 추가 성장 효과를 상쇄하는 조정은 P0~P3에 포함하지 않는다.

### 4.2 기존 계정의 새 보상

- 이미 Lv6·12·15인 영웅은 해당 마일스톤을 별도 구매 없이 인정한다.
- 이미 받은 카드·불꽃·리미티드 조각은 변환·회수하지 않는다.
- 신규 도장은 업데이트 이후 유효 전투부터 센다. 과거 판 수 전체를 도장·패스에 일괄 환산해 신규 보상 수백 회를 발생시키지 않는다.
- 첫 영웅 선택권은 기존 계정에도1회 제공한다. 고른 영웅이 이미 있으면 공개된 동급 선택 카드 보상으로 바꾸며 사라지지 않는다.
- 기존 일일 퀘스트는 P3에서 제거하지 않는다. **새 시스템만 진행도 기반**으로 만든다. 일일 보상의 추가 이관은 별도 검토한다.

### 4.3 저장·진행 중 판

- `rtd.progress`의 신규 필드는 읽을 때 기본값. 기존 키·ID 의미 변경 금지.
- 실제 저장 버전 변경은 구현 시 필요 필드와 호환 동작을 검증한 뒤 정한다. 기획 문서 작성만으로 v2→v3를 선언하지 않는다.
- sim 규칙이 바뀌는 P1·P2에서는 `SIM_VERSION`을 구현 단위로 올리고 리플레이·판 입력 스냅샷을 갱신한다.
- 진행 중 판이 새 sim과 호환되지 않으면 저장소의 기존 정책에 따라 **기존 판을 runId로 한 번만 정산**한 뒤 새 판을 시작한다. 계정·보상·재화는 유지한다.
- “계정 약화 없음”과 “모든 이전 판을 새 sim에서 그대로 이어 함”을 동일한 약속으로 쓰지 않는다.

## 5. 진행도 보상 규칙

### 5.1 유효 전투와 장기 판의 보상

| 용어 | 초안 정의 |
| --- | --- |
| 유효 전투 | 치트 없는 지원 모드에서 **10웨이브 이상을 실제 완료**하고 정산된 판 |
| 완료 웨이브 | 해당 웨이브가 종료된 사건으로 측정. 단순히 들어간 웨이브 번호와 구분 |
| 탐험 도장 | 유효 전투1판당1칸 |
| 보급 진행 | 유효 전투의 완료 웨이브를10단위로 환산. 남은 진행은 보존 |
| 보급 상자 | 누적 보급 진행10마다1개. 긴 판은 여러 개 지급 |
| 성장 선택 | **보급3개마다**1회. 목표는 표준 10웨이브 완료 전투3~5판마다 뚜렷한 성장; 긴 판은 더 빨리 성장 |

예: 완료9웨이브에서 끝난 판은 기존 정산만 받고 신규 도장·보급은 없다.
완료27웨이브 판은 도장1칸·보급2개·보급 진행7을 받는다.
다음 유효 전투에서 완료13웨이브면 진행7+13=20이므로 보급2개, 잔여0이다.
완료80웨이브의 긴 판은 보급8개를 받는다. 보상을 받기 위해10웨이브마다 포기하도록 유도하지 않는다.

- 하루 횟수 제한·자정 초기화·주말 가중치·미접속 패널티는 없다.
- 날짜·시계 변경은 새 도장·패스·보급에 영향을 주지 않는다.
- 기존 보상은 유효 전투 기준 아래에서도 원래 규칙대로 지급한다.
- 진행 중 판 불러오기·중복 정산·이전 저장 재시도는 **runId 지급 장부**로 한 번만 반영한다.
- 개발자 치트 판·테스트 보상은 기존 정책과 분리하여 정식 성장 진행을 늘리지 않는다.
- 마지막 지원 모드·누적 진행·정산 시점 규칙은 P0에서 하나의 메타 보상 장부로 고정한다.

### 5.2 반복 가능한 탐험 도장

- 28칸을 유효 전투28회로 채운다. 매일 접속이나 연속28일 조건이 아니다.
- 7/14/21/28칸에 큰 보상을 배치하고, 28칸 뒤 다음 묶음으로 넘어간다.
- 늦게 받아도 기한 만료 없음. 누적된 칸·미수령 보상 보존.
- UI 이름은 **탐험 도장**. “오늘 출석”으로 표시하지 않는다.

### 5.3 성장 선택과 성장 속도 목표

- 보급3개마다 목표 영웅 성장 재료 또는 주력 유물 조각 중 선택하는 초안을 둔다.
- 영웅 선택은 보유 영웅을 대상으로 카드·불꽃 병목을 함께 본다. 높은 등급이라는 이유로 선택 보상에서 영구 제외하지 않는다.
- 성장 재료 꾸러미는 목표 영웅의 다음 레벨 비용을 화면에서 보여 주고, 그 비용에 맞춘 지원량을 정한다.
- “1회 지원으로 반드시1레벨 상승” 여부는 비용·지원량 측정 후 확정한다. 보상 카드만 주고 불꽃 부족으로 계속 막히는 설계는 반려한다.
- 이미 최대 레벨인 영웅은 선택 불가 이유와 다른 선택지를 보여 준다. 지원을 무가치하게 소비시키지 않는다.
- 주력 유물은 **50~70회 유효 전투**에서 완성 가능한 직접 조각 경로를 별도로 계산한다. 하루5판 가정이면10~14일이며 **플레이 목표**다.
- 첫12종 수집·일부 조합 성형은1~2개월 내 목표. 모든65영웅·24유물 만렙을 같은 기간에 보장한다는 뜻은 아니다.
- 성장 목표는 획득량 표·누적 비용·선택 보상·천장·중복 교환을 합산해 P0/P2에서 재현 가능한 계산으로 검증한다.

### 7.2 획득·천장·강화

- 처음 유물은 가이드 완료 보상으로 첫12종 중1개 선택. 경제 유물만 강제하지 않는다.

- **매10회째**는 미보유 유물, 전부 보유했으면 최저 레벨 유물에서 보장한다. 동률 선택은 시드·순서가 고정된 방식.
- 카운터는 계정에 보존한다. 앱 종료·무료/상점 열쇠 구분으로 초기화하지 않는다.
- 원하는 유물은 목표로 지정한다. 신규 보급1개당 목표 조각1개를 주는 후보로, 무작위 뽑기와 별도 직접 성장 경로를 둔다.
- 남는 조각5개→지정 조각1개. 여러 유물 조각을 섞어5개를 낼 수 있게 하고, 소비할 종류·수량을 보여 준다. 미보유 유물의 자동 해금 여부도 UI에 명시한다.
- 강화 비용 초안: 해금1개, Lv1→10 추가 조각 **1/2/3/4/6/8/10/13/16**. 골드는 단계표로 별도 정의한다.
- Lv1→10 추가 조각 합계63개. 목표 조각1개/보급이면 최대63보급의 직접 경로가 생긴다. 다른 성장 선택을 고르거나 골드가 부족하면 기간이 길어지므로 골드까지 합산한다.
- Lv5 한도 유물은 해당4개 구간만 사용한다. 더 긴 비용표를 억지로 적용하지 않는다.

- 매 레벨 실제 효과가 증가하는지 정수 변환·bp 단위에서 검사한다.

### 7.3 보급과 열쇠의 단일 장부

보급1개당 열쇠1개·목표 조각1개라는 후보를 사용한다.
P2가 먼저 들어갈 때는 정산 화면의 탐험 보상으로 표시하고, P3에서는 동일 지급을 보급 상자 화면으로 감싼다.
**P2 직접 지급과 P3 상자 지급을 동시에 적용하지 않는다.**
보스·패스·도장·상점의 추가 열쇠는 같은 경제 시트에 출처별로 합산해 목표 기간을 다시 계산한다.

### 7.4 경제 보조 상한

- 새 효과 없이 기존 판이 재현되는 것을 먼저 확인한다.
- 기존 돈 도박·이자·일꾼 값을 낮춰 새 유물의 여유를 만들지 않는다.
- 보유금 공격력은 상한 적용 후 공격력을 계산한다. 상한을 넘긴 돈에 계속 비례하지 않는다.
- 도박 꽝 환급은 지급된 당첨금이 아니라 해당 시도의 비용을 기준으로1회만 처리한다. 환급이 환급·잭팟·재시도를 재귀 호출하지 않는다.
- 경제형/전투형/혼합형을 같은 보급·계정Lv·시드에서 비교한다. 도달 웨이브·보스시간·소환·보유금·투자량을 함께 기록한다.
- 경제형이 전투형을 일관되게 압도하면 **공개 전 신규 유물 후보만** 조정한다. 공개 뒤 기존 계정 하향이 필요한 문제는 별도 결정 대상으로 올린다.
