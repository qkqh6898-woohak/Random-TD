### 전체 실행의 실패 분류와 후속 확인

- **실제 회귀 수정**: 위 HUD에 돈·인원 줄이 생겨 412×915에서 칸 크기가 171로 줄었다. 아이콘과 HUD 여백을 조정해 **178**로 회복했고, 기존 최소 176 검사와 큰 유닛 선택·이동 8개가 재통과했다.
- **그림 교체에 따른 검사 갱신**: 일꾼·소환의 SVG 선택자는 실제 로드된 WebP 주소·256px 크기로 바꿨다. 그림 누락 시 SVG/이모지 대체와 버튼 동작도 새로 검사한다. 종족 선택 검사는 details를 먼저 펼친다.
- **준비 단계와 관측 경쟁 보완**: G2 승급 카드 검사는 debugTower로 생긴 준비용 카드 3장을 제외한 뒤 실제 승급 시 정확히 1장 증가하는지 확인한다(원래 main도 2가 아닌 5로 실패). 도전 보상은 HP를 낮추기 직전 같은 평가에서 돈을 기록해 +20원 검사를 유지한다. 짧아진 판매 패널 때문에 노말 궁수가 아래에 들어갈 수 있어 시트 상호 배제 검사는 위에 붙는 히어로 수호 기사로 준비하고, 위쪽 배치와 실제 강화 버튼 히트 영역도 검사한다. 아래 패널이 메뉴를 덮는 기존 설계는 바꾸지 않았다.
- **기존 main에서도 재현되는 실패 4건**: `e2e/hud-layout.spec.ts:134`, 412×915·360×640·320×568·915×412. 보스/도전 두 줄 배너의 끝이 한 줄 toast 예약 영역을 넘는다. `28c4ce6` 기준과 수정 브랜치에서 같은 Canvas 설정으로 각각 재현했다. 게임 소스가 동일한 `f229a8c`에서도 같은 기준이다. 이 검사의 기대값이나 배너 소스를 수정하지 않았으며 Claude 검토 대상으로 남긴다.
- **환경 제한 1건**: 단일 HTML `file://` 열기는 관리형 Chromium의 `net::ERR_BLOCKED_BY_ADMINISTRATOR`로 차단된다. 서버 없는 실행 검사를 통과로 세지 않는다. 빈 HTML도 같은 file:// 차단을 재현했다. release 폴더만 제공한 HTTP 확인에서는 **HTML 요청 1회, 추가 자산 요청 0회, 콘솔 오류 0, 내장 245개, 새 UI/일꾼 로드, 소환 1개와 잔액 900원**을 확인했다(`single-http-check.log`). 이는 file:// 검사의 대체 통과가 아닌 보완 증거다.
- 후속 Canvas 관련 29개 실행은 **24 통과 · 5 실패**였다. 그중 4개는 위 기존 배너 문제, 나머지 패널 테스트 준비는 위 설명처럼 바꾸고 **별도 1개 재검증 통과**했다. 상세 결과는 `validation.json`을 확인할 것. 전체 197개를 수정 후 다시 전부 돌린 것으로 표시하지 않는다.

## Claude 통합 메모

- `Hud.ts`, `TowerPanel.ts`, `SummonSheet.ts`, `Lobby.ts`를 수정했다. 기능 피드백 브랜치를 합칠 때 DOM 위치/클래스와 기존 콜백을 함께 유지할 것. 새로운 명령·규칙은 없다.
- 새 CSS는 `src/ui/feedback-design.css`로 분리했다. 기존 스타일보다 나중에 불러온다.
- 외부 WebP가 없는 절차 대체 그림은 기존 절차 파츠 외곽선을 유지한다. 이번 등급 색 띠는 현재 기본으로 사용되는 WebP에 적용한다.
- Android 리소스 그림만 변경했으며 서명·릴리스 설정은 변경하지 않는다. 이 작업에서 main을 푸시하거나 릴리스를 실행하지 않는다.
