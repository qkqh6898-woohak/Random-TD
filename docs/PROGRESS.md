- 검토 반영 (독립 검토 15건 모두 실제 문제로 확인하고 수정. 같은 문제를 다른 관점에서 짚은 중복 4쌍 포함):
  - **step 도중 enqueue**(major): `CommandQueue`가 take한 틱을 닫는다(`openFrom`). step 안(시스템·처리기)에서 tick을 생략하면 다음 틱으로 잡히고, 이미 꺼낸 현재 틱을 지정하면 `ok:false`(이미 실행 중인 틱). 받아 놓고 실행하지 않는 명령·남는 `pendingKeys`가 없어짐. 회귀 테스트: World 3개, Commands 2개.
  - **명령 객체**: 큐에는 허용 필드만 골라 새로 만든 `Object.freeze` 객체를 넣고 그대로 돌려준다(`Command`는 `Readonly`). 모르는 필드는 `validatePayload`가 거절(`PAYLOAD_FIELDS` 표). 새 명령을 추가할 때 `PAYLOAD_FIELDS`에 필드를 적어야 한다.
  - **최대 인원 한 곳으로**: `Commands.ts`의 `MAX_PLAYERS=4`와 World의 박아 둔 `2`를 지움. `WorldOptions.maxPlayers`(= `game.json` maxPlayers, Game 장면이 넘김), `new CommandQueue(players)`, `validateCommand(cmd, players)`. maxPlayers를 생략하면(헤드리스 테스트) players만 검사.
  - **hash**: Map 키·Set 값은 '모두 안전한 정수' 또는 '모두 문자열'만(객체·섞인 타입·소수는 `HashError`). 정수 키는 따옴표 없이 `M{1:…}`, 문자열 키는 `M{"1":…}`로 구분 → canonical 문자열 형식이 바뀌었다(아직 저장된 리플레이 없음).
  - **결정성 검사**: `Math`는 허용 목록(floor·ceil·round·trunc·imul·min·max·abs·sign·clz32·fround)을 `Math.이름` 꼴로 부를 때만 통과 → 별칭·구조 분해·`Math?.`·`Math.PI`도 위반. `eval`/`Function`·`Reflect`·동적 `import(`·`localeCompare`/`toLocale*`/`Intl` 규칙 추가, 후위 `++`/`--` 뒤 `/`는 나눗셈. 탐지 테스트 17개 추가.
  - **데이터 검사**: 종족 색 `#RRGGBB`, 맵 `spawn = 첫 웨이포인트`, `exit = 마지막 점`(loop면 첫 점으로 복귀), `pathLength = 맨해튼 길이 합`, `turns = 방향 전환 수`(loop는 닫히는 전환 포함, `measurePath`), 길이 0 구간 금지. M6 생성 맵도 이 검사를 통과해야 한다.
  - **전역 오류 화면**: `src/ui/fatal.ts` — window `error`·`unhandledrejection`을 받아 한 번만 오류 화면(게임 루프 `sleep`). 장면 create·update 안의 예외도 콘솔에만 남지 않는다(E2E로 확인).
  - **⏸ = 일시정지 메뉴**(UI.md 4.6): 바로 타이틀로 가지 않고 `PauseMenu`([계속]/[타이틀로])를 연다. 열린 동안 TickClock 배속 0(E2E로 틱 정지 확인), 앱이 백그라운드로 가도(Phaser `hidden`) 자동으로 열림. 배속 칩과 간격을 넓힘.
  - **터치 크기**: `.btn-chip` 최소 `max(11cqw, 44px)` (412px 무대에서 약 45px). E2E가 HUD 칩 44px 이상을 확인.
  - **화면 읽기**: `#ui-root`의 `aria-live` 제거, toast 층만 `role=status aria-live=polite`. HUD 틱·시간은 `aria-live=off`, 시간은 `role=timer`.
  - Game 장면 표식 속도는 `enemies.json` slime.speed에서 읽음(코드 상수 제거). 헤드리스 통합 테스트는 seq를 직접 적고 실행 순서(틱→플레이어→seq)를 단언.
  - 테스트: Vitest 137 → **184개**, E2E 3 → **5개**.

- 주요 결정:
  - **공격 타이머**: 틱마다 ① 누적값 ≥ 1회분(1000 × 20)이면 찰 때마다 공격 ② 공속 × 1000 충전 ③ 대상이 없어 멈췄으면 1회분까지만 보관. 공격을 충전보다 먼저 봐서 간격이 정확히 `20000 ÷ 공속` 틱(1회/초 = 0·20·40틱), 12.5회/초는 어느 1초든 12~13회, 20회/초 초과면 한 틱에 여러 번. 소환 직후는 준비 상태 → 사거리에 몹이 있으면 그 틱에 쏜다.
  - **기본 피해 = 공격력 × 100 정수 + 타워별 나머지**: 데이터 공격력에 소수(견습 마법사 6.5, 북치기 4.5 …)가 있어 정수 피해로 바로 자르면 DPS가 최대 8% 틀어진다 → ×100 정수로 들고 나머지(0~99)를 타워에 이어 간다(6, 7, 6, 7 …). 몹 체력 단위는 그대로(M1 표·2^53 여유 유지). ※ 검토 반영으로 방어 감소까지 ×100 단위에서 계산하고 합에 한 번만 자르도록 바뀜 (아래 '검토 반영 (독립 검토)').
  - **"물리만"의 해석**: 피해 감소 A ÷ (A + 100)을 물리(방어력)뿐 아니라 마법(마법 저항)·고정(감소 없음)에도 같은 함수로 적용했다. 기본 덱 노말의 견습 마법사가 마법 피해라 물리만 넣으면 0 피해 타워가 되기 때문. 관통·치명타·공격력% 배율·약화·보스 배율·공격 형태(광역·관통·연쇄·다중)·상태 이상은 M3-4·M3-5·M3-6 (지금은 모든 공격이 단일 대상).
  - **피해 계산 시점**: 1회 공격력(방어 전, ×100 정수)은 쏠 때 정해 투사체에 싣고, 방어·마법 저항은 도착할 때 대상 값으로 깎은 뒤 쏜 타워의 나머지를 더해 정수로 자른다. M3에서 약화·빙결(받는 피해 +%)은 도착 때 ×100 값에 곱하면 된다.
  - **즉시/투사체**: 근접(melee·melee_aoe)·전체(global)는 즉시, 나머지는 투사체(GDD 5.2 "근접·광역 일부는 즉시"). 투사체는 대상의 지금 위치를 따라가며(초속 12칸 > 몹 최고 2.6칸) 남은 거리 ≤ 600이면 도착. 새 투사체는 쏜 틱에 바로 한 번 움직인다 → 비행 틱 수 = ⌈거리 ÷ 600⌉.
  - **선두**: 캠페인 = 진행도 최대(같으면 작은 ID), 무한 모드 = 가장 오래 살아 있는 몹(가장 작은 ID, GDD 5.3). ※ 처음에는 무한 모드도 진행도 최대였다가 검토 반영으로 바뀜.
  - **투명 몹은 대상이 아니다**(GDD 5.7): 감지·드러남은 M4. 35단계부터 투명 도둑은 맞지 않고 지나간다.
  - **처치 보상은 몹이 나온 단계 기준**(M1 Spawn이 이미 `Mob.reward`에 계산) → 9단계 몹을 10단계에 잡아도 10원.
  - **전투가 패배 판정보다 먼저**: 같은 틱에 151번째 몹이 나와도 그 틱의 처치를 먼저 센다(UI.md 9장).
  - **신 판정은 매번 난수 1개**: 확률(데이터)이 바뀌어도 소환 흐름의 사용 횟수가 같다. 0.01%에 걸리면 신 3종 중 하나를 그대로 놓는다(전용 능력·강림 연출은 뒤 마일스톤, 지금은 "👑 {이름} 강림!" 알림만). ② 레어 직행은 확률을 주는 것이 없어 난수를 쓰지 않는다.
  - **덱은 판 시작 때 정해지는 입력** → `MatchContext.decks`(해시 밖). M3-12 리플레이는 시드와 함께 덱을 기록할 것.
  - **지갑은 판에 하나**(state.gold). 타워에 `owner`는 남겨 두었고, 2인 지갑 분리는 M13.
  - 화면이 sim 상태로 소환을 미리 검사해 바로 알림을 띄우고, sim이 실행 틱에 다시 검사해 거절하면(같은 틱 연타 등) `summonFail` 사건으로 같은 알림. 연출은 **최근 3틱의 사건에만** 만든다 → 빨리 감기·높은 배속에서 사건이 수천 개 쌓여도 화면이 멈추지 않는다. 한 프레임 피해 숫자 16개·불꽃 12개, 동시에 나는 동전 24개 한도.

- 주요 결정:
  - **보스는 상태이상 저항(데이터 70%)을 겹쳐 곱하지 않는다**: ENEMIES.md 보스 표의 '상태이상 저항 70%'와 GDD 5.5 보스 열 '지속 30%'는 같은 뜻으로 보고 보스 규칙(둔화 절반·지속 30%)만 쓴다 (겹치면 DEV_PLAN 예시 '보스에 둔화 60% → 30%'가 9%가 됨). 보스가 아닌 몹만 ccResist로 둔화 세기·기절·정지·**빙결** 지속을 줄인다(빙결도 '일시 정지'라 저항 대상에 넣음).
  - **효과 시작 시점**: 걸린 틱 T부터 약화·표식이 같은 틱의 다음 공격에 적용되고, 이동에는 T+1틱부터 정확히 지속 틱 수만큼 (until = T + 1 + d). 지속시간 '갱신'은 더 늦게 풀리는 쪽으로(짧은 기절이 긴 기절을 줄이지 않음). 면역 1초는 마지막 행동 불가가 끝난 틱부터 — 걸려 있는 동안 다시 걸면 갱신되므로 기절 두 개를 번갈아 걸면 계속 묶인다(문서대로).
  - **원소 효과 = 데이터**: 화상은 towers.json `dot`이 있는 타워(화염 마법사·원소 지배자)만. 용 소환사·대마법사는 원소가 화염이지만 dot이 null이라 화상 없음(데이터가 정답). 독(독 궁수 5중첩)·출혈(군견병)도 dot으로 자동 동작(해금 타워라도).
  - **지속 피해**: 초당 피해 = 쏠 때의 1회 공격력 합 × 공격력% × perSec (치명타 제외), 0.5초마다 고정 피해(약화 곱함, 보스 배율·방어 무시). 중첩은 (출처 타워 종류, 종류)별 — 다른 타워의 화상은 따로 중첩.
  - **운석 = 현재 체력 % 고정 피해**: 방어·마법 저항을 무시하고 약화만 곱한다('현재 체력 %'가 높은 단계에서도 그대로 들어가게, 최소 1). 문서의 '마법 관통 30%'는 대마법사 기본 공격 스탯.
  - **주기 능력**: 놓인 뒤 주기만큼 지나야 첫 발동, 승급하면 새 엔티티라 처음부터. 진흙 웅덩이·시간 정지·운석·병사는 대상(사거리 안 몹/드러난 몹)이 없으면 기다렸다가 생기면 바로 (빈 맵에 낭비하지 않음). 연금술사 돈은 몹이 없어도 10초마다.
  - **상인은 상인마다** 처치 1마리당 돈(문서 '1마리당'을 상인 하나의 효과로 해석). 오라·행운의 여신·도박꾼 값처럼 '판 위에 있으면 주는 값'은 같은 타워 비중첩(GDD 5.6).
  - **오라는 같은 주인끼리만** (2인 판에서 남의 타워를 버프하지 않음 — 협동 규칙은 M13에서). 끄는 중(hold)인 오라 타워도 원래 칸에서 계속 준다.
  - **소환 병사 자리** = 소환사 칸 중심에서 가장 가까운 경로 지점(같으면 앞 구간). 닿는 거리 0.5칸, 같은 몹은 한 번, 순환 맵은 진행도가 음수가 되어도 계속(위치는 나머지), 스테이지 맵은 출발점 뒤로 넘어가면 사라짐. 병사 피해에는 특색·치명타 없음.

  - **알약 자리**: 맵 위(6~8, 10칸)에 떠 소환 탭을 가로채던 [🃏 카드 고르기] 알약을 **HUD 아래 띠 타워 수 옆**(`hud.choiceSlot`, `display: contents`)으로 옮김. 알약이 보이면 소환 안내는 숨기고, [⬆ 승급 가능 n]도 보이면 알약은 그림 글자(🃏/✨)만 (412px에서 띠가 넘치지 않게, aria-label은 그대로). E2E: 알약이 띠 안, (6~8, 10) 칸 중심 = 캔버스, 띠 scrollWidth ≤ clientWidth.
  - **운석 = 전체 피해**: 대마법사 운석 `RawHit`에 `area: true` → 방패병 보호막이 2배로 받는다 (ENEMIES.md 6장, 전투 형태 '전체'와 같게). `RawHit.area` 주석 갱신. 리플레이 결과는 그대로(방패병 + 대마법사 조합이 없음).
  - **데이터 주도**: 카드 창 부제 `offer.boss × rules.bossEvery`(10을 박지 않음), 군주 직속 이름은 `enemies.json hierarchy.lord.guardName` 새 필드 → `legionNameMap`(hudModel, 순수)과 `gen_tables.py`가 같이 읽는다. 이 필드 때문에 **데이터 지문만** 바뀌어 리플레이 5개를 다시 만들었다 (주기 해시·끝 해시는 그대로 — diff는 dataHash 줄뿐).
  - **투명 몹 경고 둘째 줄**: 고정 문구(기본 덱에 없는 정찰병 포함) → 내 덱의 감지 타워(`deckDetectNames`, towers.json detect ≠ none, 덱 등급 순) '💡 덱의 감지 타워: 저격수·그림자 암살자', 없으면 '💡 덱에 감지 타워를 넣어 보세요'.
  - **킹 슬라임 분열 크기**: `MobSprite.scaleMul`을 저장하고 `MobLayer.sync`에서 배율(정예·작게·조각)이 바뀌면 그림을 다시 만든다 → 조각 둘 모두 0.8배. E2E(20단계 분열 → `drawnMobScale` 둘 다 0.8).
  - **보스 단계 알림 중복**: 보스 등장 배너를 한 줄 '👑 10단계 · 질풍 군단 · 대장 「박쥐 여왕」'(`bossArrivalText`)로 합치고 같은 프레임의 '👑 10단계 보스 단계!' 알림은 생략 → 두 번째 알림이 맵 0~1줄(보스 시작점)을 가리지 않는다. 배너를 못 띄운 프레임(빨리 감기 등)에는 단계 알림을 그대로 낸다.
  - **편대 예고 배너 3줄**: 배너 줄은 줄바꿈하지 않고, 넘치는 줄은 `fitBannerLines`(UiRoot)가 글자를 폭에 맞게 줄인다(원래의 60%까지). 문구는 UI.md 8장 그대로 — 412px에서 6종 모두 제목 13.3~15.3px 한 줄 + 힌트 한 줄 = 높이 53~57px (예전 72px). E2E가 제목·힌트 각 한 줄·넘침 없음을 확인.
  - **패배·일시정지 화면 위 알림**: `UiRoot.clearToasts()`를 패배 화면·일시정지 메뉴를 열 때 부른다 (알림 층이 화면 층보다 위라 '패배' 제목을 가렸다). E2E: 패배 뒤·일시정지 뒤 알림 층 비어 있음.
  - **가득 찬 판의 아래 띠 안내**: [⬆ 승급 가능 n]이 보이면 '빈 칸이 없어요'도 비운다 (60px 칸에서 '빈 칸…'으로 잘렸다, 가득 찬 것은 '71/71'이 보여 줌). M2 E2E 갱신.
  - **죽은 입력 정리**: `HudInput.bossNames`와 Game.ts의 캠페인 배치표 이름 계산을 지움 (HUD 보스 이름은 실제 보스 데이터에서).
  - 테스트: Vitest **736개** (+6: 운석 보호막 ×2, 카드 부제 bossEvery, legionNameMap, 감지 타워 문구 2, 보스 등장 배너; view-m3 안내 기대값 갱신), E2E **60개** (+2: 승급의 축복을 패널로 = 바텀 시트 하나, 킹 슬라임 분열 크기; 기존 M4 E2E에 알약 자리·보스 배너 하나·패배/일시정지 알림 비움·감지 타워 문구·편대 배너 두 줄·[바꾸기] 그림 확인 추가).

## M5 — 첫 10단계 업데이트 (상태: 타이틀·강화·미션·온보딩 작업 완료)

- 타이틀에 주사위 소환 일러스트를 WebP로 번들했다. 시작 버튼은 DOM 버튼이며, 로고의 접근성 이름과 디버그 캠페인 진입 동작을 유지한다.
- 하단 강화·미션 패널은 기존 명령을 사용한다. 강화는 레벨·효과·가격을 표시하고, 미션은 달성 보상을 위에 모아 개별·일괄 수령을 제공한다. 게임 시간은 흐르며, 맵이나 다른 메뉴를 누르면 시트가 닫힌다.
- 준비 단계에 추천 배치 칸 세 곳을 표시한다. 첫 소환 뒤 준비 완료 명령으로 1단계 진입을 앞당길 수 있다. 승급 패널을 열면 실제 결과·재료 칸을 표시하며 첫 승급 후 결과의 이름과 공격 형태를 알려준다.
- 기본 타워 5종에 헤드램프와 곡괭이, 뾰족한 귀와 단검, 망토와 큰 활, 두건과 지팡이, 투구와 방패를 적용했다. 낮은 채도의 잔디와 밝은 경로로 전투 화면 대비를 높였다.
- `firstInfiniteHpMul`은 무한 모드 첫 박쥐 여왕에만 적용한다. 공통 배율 ×45, 무한 첫 등장 배율 ×4.2. 9단계에 박쥐 여왕을 예고하고, 비행 중 사거리 제한과 시간 초과 시 남은 체력을 보여준다.

| 시드 61~80, 기본 덱 Lv1 | 운용 | 처치 | 처치까지 | 시간 초과 시 남은 체력 |
|---|---|---:|---|---|
| 준비 60초 | 소환·승급 | 9/20 | 4~39초 | 0~41% |
| 준비 60초 | 소환·승급 + 강화·미션 | 16/20 | 7~60초 | 3~24% |
| 7기 배치 후 준비 완료 | 소환·승급 | 9/20 | 5~57초 | 5~41% |
| 7기 배치 후 준비 완료 | 소환·승급 + 강화·미션 | 13/20 | 26~59초 | 3~26% |

비교 봇은 경로 가까운 칸부터 배치하고, 7기부터 일꾼을 3명까지 고용하며, 12기 이상이면 승급한다. 강화·미션 운영은 수령 가능한 미션과 일반 강화 Lv6까지 우선 적용했다. 초기 체력 비율과 처치 시간은 정수로 반올림했다. 표는 특정 운용의 재현 결과다.

- 휴대폰 캡처 `docs/screens/M5.png`는 1단계 미션 보상 수령 전 상태다.
- 일반 시작 시드 61을 브라우저에서 시뮬레이션 시간만 앞당겨 검증했다. 첫 승급, 9단계 예고, 10단계 비행 안내, 보스 처치·카드 선택까지 디버그 명령 없이 완료했다.
- 검증: Vitest 800개, 타입·데이터·결정성 검사, 프로덕션 빌드, Playwright 63개(수정 후 재실행 포함). 빌드의 타이틀 WebP는 약 358KB다.

## M6-5 — 진행 중인 판 자동 저장·이어 하기

## M6-9 — 타이틀풍 캐릭터와 휴대폰 조작 개선

- 타이틀 그림을 참고해 광부·고블린·궁수·견습 마법사·전사와 박쥐 여왕을 그렸다. 투명 WebP를 앱에 넣고, 타워 그림을 기존 발밑 원점과 등급 별에 맞춰 합성한다. 브라우저 캡처 `docs/screens/M6-chibi.png`에서 여섯 그림의 전투 배치를 볼 수 있다.
- 하단 [소환]은 입구 쪽 추천 칸부터 사용한다. 추천 칸에 자리가 없으면 근처 빈 칸을 찾는다. 직접 칸을 누르는 조작과 빠른 소환은 비용 검사와 연타 제한을 공유한다.
- Android 뒤로 가기는 화면에서 열린 창을 먼저 닫는다. 전투 화면에서는 일시정지와 이어서 진행에 쓴다. Android v0.1.5는 버전 코드 6과 기존 서명을 사용한다.
- 서명과 내장 자산을 검사했다. 오프라인 브라우저에서 v0.1.4의 진행 중인 판과 강화를 이어서 불러왔고, 320px 화면에서 빠른 소환과 뒤로 가기 이벤트를 확인했다. 안드로이드 실기기 설치 검증은 남아 있다.
- 검증: Vitest 805개, 타입·결정성·데이터 검사, 프로덕션 빌드, Playwright 66개 통과.

## M6-10 — 소환·승급 주사위 효과와 화면 흔들림 설정

- 소환한 칸에서 주사위와 등급 색 소환진이 보인다. 승급할 때는 재료 칸의 주사위가 결과 칸에 모여 소환진이 펼쳐진다. 한 화면에 동시에 펼쳐지는 주사위 연출은 12개까지다.
- 일시정지 메뉴의 [화면 흔들림] 설정을 기기에 저장한다. 설정을 처음 열면 기기의 동작 줄이기 환경을 따른다. 끄면 카메라 흔들림을 멈추고 골드 부족 칸은 위치를 움직이지 않고 색으로 표시한다.
- `docs/screens/M6-dice.png`는 소환 주사위가 떠오른 412px 화면이다. Android v0.1.6은 버전 코드 7과 기존 서명을 사용한다. 내장 자산을 오프라인 브라우저로 실행해 v0.1.5의 판 이어 하기와 새 설정 저장을 확인했다.
- 검증: Vitest 805개와 타입·결정성·데이터 검사 및 프로덕션 빌드 통과. Playwright 67개 중 기존 보스 골드 검사에서 측정 타이밍으로 실패한 1개는 재시도로 통과했다.

## M6-11 — 소환·승급 효과음과 볼륨

- 소환에는 짧은 타격음과 오르는 음, 승급에는 높아지는 세 음을 사용한다. 플레이어의 성공 이벤트에 맞춰 Web Audio로 합성하며 같은 효과의 짧은 연타를 한 번으로 묶는다.
- 일시정지의 [효과음 크기]에서 0~100%를 5% 단위로 조절하고 [미리 듣기]로 확인한다. 기본값은 40%, 0%는 음소거다. 볼륨은 진행 중인 판과 별도로 기기에 저장한다. `docs/screens/M6-audio.png`는 412px 일시정지 메뉴다.
- Android v0.1.7은 버전 코드 8과 이전 서명을 사용한다. 오프라인 브라우저에서 v0.1.6의 진도 복원, 효과음 파형 출력, 앱 재실행 뒤 볼륨 복구를 확인했다.
- 검증: Vitest 805개, 타입·결정성·데이터 검사, 프로덕션 빌드, Playwright 68개 통과.

## M6-12 — GitHub Android 배포

- Android 래퍼와 SDK 준비·APK 빌드 스크립트를 배포 브랜치에 추가했다. GitHub Actions에서 공개 SDK와 컴파일러의 해시를 확인하고 빌드한다.
- v0.1.7 서명 APK를 다운로드 경로에 두고 서명과 빌드 내용이 일치할 때 GitHub Releases에 게시하도록 구성했다. 서명키와 비밀번호 파일은 로컬에 보관한다.
- 로컬에서 빌드한 APK와 기존 서명 APK를 풀어 비교했다. 서명 메타데이터를 제외한 파일이 모두 일치했다.
