### Notes on confirmed-safe areas (requested focus items with no defect found)

- **Determinism / replay**: the fuzz (12 seeds, ≤40k ticks, all live commands, debug and non-debug, stages up to 243) had no crash or `HashError`. The checkpoint→restore hash always matched. Replay-from-0 always equalled the live hash, and restored and replayed runs stayed equal 400 ticks later. Iteration is by `EntityStore.list()` (ID order) everywhere I checked. There is no float in state, and `check-determinism` covers `src/sim`. The `towersDirty` closure in `Mission.ts:228` is not checkpointed, but that is harmless: the first tick after a restore re-checks a census that is order- and position-independent.
- **Late-game integer range**: `curves.hp[500] ≈ 9.6e13`. The worst spawn is ×60 (chaos dragon) ≈ 5.8e15 < 2^53, and elites (×5) or other mobs are smaller. `mulBp`/`mulDiv` *throw* on overflow rather than silently losing precision. `reduceDamage` would need a single raw hit > ~9e7 damage (×100 scale) to overflow, which is far beyond any reachable build. `transcendCost` tops out at 8.47e15, which is safe. Not a risk today (but note the HP curve clamps at stage 500, so infinite mode stops scaling after 500).
- **Stage/boss timing**: the boss stage length is `max(stageTicks, bossTimeTicks)` and the deadline is checked before the stage advances. `readyNow`/`debugSkipStage` paths look right. Defeat at `mobs > mobLimit` matches the doc (150 survives, 151 loses).
- **Auto-sell vs auto-merge (Game.ts:2305-2392)**: `autoSellMinRank` correctly excludes ranks auto-merge handles. Auto-merge sends one `mergeStack` per tick and is suppressed while dragging, in move mode or paused. Selling uses `topTowerAt`, and since stacks are uniform (except H1) the top is always a same-type just-summoned tower.
- **Hold-repeat / listeners**: HUD and sheet holds are detached in `destroy()`. Game's SHUTDOWN unregisters window, scale and input listeners plus the ResizeObserver. Toast and cut-in timers are self-limiting or stopped.

## Risky duplication (for the consolidation step)

1. **Grade order disagrees across 4 places**: `lobbyModel.ts:34 GRADE_RANK` (hidden 7 > god 6) vs `rules.ts:133 GACHA_RANK` + `rules.ts:1053 gradeRank` (hidden ≡ legend 5 < god 6) vs `gradeGuideModel` / UI.md text (레전드 < 신화 < 신) vs `characterLooks.json` scale (신화 > 신). The rename work must pick one table. Note that `gradeRank` feeds pity "good result", auto-sell and auto-merge.
2. **Korean grade-name tables ×6** (`lobbyModel GRADE_KO`, `towerPanelModel GRADE_NAMES`, `choiceModel:73`, `Gallery:42`, `g1Models GACHA_GRADE_NAMES`, `sheetModels GRADE_SHORT`) plus names baked into `game.json` upgrade names and `missions.json` text. The 신화→리미티드 rename will miss some.
3. **Hard-coded grade lists**: `DECK_GRADES`, `CARD_GRADES`, `settings.ts AUTO_MERGE_GRADES`, and its copy at `Game.ts:2507 (['normal','rare','unique'] as const)[rank-1]`, plus `Gallery FILTER_GRADES`.
4. **Two parallel rule sets for summon/merge/move**: legacy `Summon.summon`, `Merge.merge/mergeAll/mergeableGroups/sameKindTowers` and `Move.moveTower` live beside the stack versions (`Board.summonStack`, `mergeStack`, `moveStack`). Any rule change (cost curve, unit cap, sell value) must be mirrored or the legacy paths gated (see L2).
5. **Badge logic** is scattered (research §5d, 30 sites). There is a confirmed condition mismatch (L7). `claimableQuests` is recomputed in 3 places, and in-match badges are recomputed per frame while lobby badges recompute on `progress.subscribe`.
6. **Sell value derived from `summon.cost`** inside `buildTowerValues` (rules.ts:1024). The planned decoupling should remove this coupling (H2).

## Not bugs, but worth noting

- **Gamble EV is > 100%** by design (feedback #59, ~137% with jackpot). Combined with interest and no gold cap, the economy retune should re-check it together with H2.
- **Auto-merge chain** (`chainFrom`) can consume a pre-existing full stack of the *result* type: auto-merge "노말" can merge a full rare stack the player was holding for a recipe. This is documented ("연쇄도 손으로 누른 승급과 같다"), but surprising with a rank-limited auto setting.
- **Runs abandoned via [새 게임]** give no rewards (the dialog warns "지워져요"). Consider settling them, as with M2a.
- **Schema evolution for the concurrent work**:
  - `parseProgress` rebuilds the object field by field and the store saves at boot, so a new `ProgressState` field (불꽃) must be added there or it is wiped on every launch.
  - `parseSettings` also drops unknown keys.
  - A new optional `MatchState` field must go into `OPTIONAL_STATE_KEYS` (or restore throws, which is fine since saves are discarded on version change anyway).
  - A per-summon cost counter belongs in `MatchState` (hashed) and must be per-player if M13 matters; research notes `summonDiscount`/`summons` are global.
- **Release pipeline**: `android.yml` signs and publishes on every main push without E2E or an APK smoke run (accepted policy in CLAUDE.md §7). Missing secrets produce `signed=false` with only a `::notice` (no release, run green).
- **Cosmetic or harmless**:
  - Comment drift: Game/codex comments say "조각 n/20" while data is `unlockFragments: 5`.
  - `Game.syncG1` checks codex discovery only on frames where `tick % 10 === 0`, which at ×8/×16 can be delayed by many frames (it eventually fires).
  - Escape (desktop) closes the bottom sheet behind the pause menu.
