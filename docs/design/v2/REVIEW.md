# V2 디자인 검토·통합 안내

모바일 UI 디자인 단계 B~G와 칸 투명화의 검토 안내다. 공통 main 기준은 `3abfda6e943a5c0bccbb2a0710c80ceac00f57e9`다. 아래 PR은 검토용이며 main 병합·푸시·서명 릴리스를 실행하지 않았다.

| 단계 | 브랜치 / 검토 대상 | 범위 |
| --- | --- | --- |
| B | design/v2-pr-b / main, #73 | 공통 토큰·컴포넌트·오리지널 SVG·로컬 글꼴·개발 갤러리 |
| C | design/v2-pr-c / B, #74 | 첫 로딩·전환 로딩 |
| D | design/v2-pr-d / C, #77 | 로비 HUD·탭·주요 행동 |
| E | design/v2-pr-e / D, #78 | 영웅 7등급 카드·미보유·진행 표시 |
| F | design/v2-pr-f / E | 상점·도감·캠페인·상세·퀘스트·모집·보상·설정 팝업 |
| 칸 | design/field-context / main, #79 | 평소 투명, 선택·이동·판매·승급·강화 때 관련 칸 표시 |
| G | design/v2-pr-g / design/v2-battle-base | 자연 필드·전투 HUD·메뉴/통계·종이 시트·치명타·WAVE 띠 |

`design/v2-battle-base`는 E 이후 F와 필드 #79를 합친 **검토 전용 기준 브랜치**다. G PR의 변경 목록에는 G만 나오게 하고, 누적 실행 화면에서는 B~G와 필드를 함께 볼 수 있다. 이 기준 브랜치를 main 배포 브랜치로 취급하지 않는다.

검토는 B→C→D→E→F 순서와 독립 필드 #79, 마지막 G 순서가 적합하다. 실제 통합은 Claude가 전용 통합 브랜치에서 최신 main과 충돌·소유권을 확인하고 한 번에 검증한 뒤 별도 통합 PR로 정리한다. 개별 디자인 PR을 차례로 main에 병합하면 각 병합마다 릴리스가 발생할 수 있으므로 이 전달은 main 병합 승인이 아니다.

## 검사와 소유권

- 단계별 변경 파일·자산·4개 폭 캡처는 각 `docs/design/v2/*/PR-*.md`, `validation.json`, `screens/`에 있다. F/G의 `regression.json`은 F+G+필드를 함께 적용한 동일한 전체 회귀 결과이며 두 번 실행했다고 세지 않는다.
- G의 `bundles.json`은 배포 빌드와 단일 HTML의 HTTP 실행을 검사한다. 관리형 Chromium의 `file://` 정책 차단을 HTTP 성공으로 덮지 않는다. 실제 Android 장치 검사는 별도다.
- sim/meta/save/data/경제/ID/명령/저장 형식/SIM_VERSION/오디오/네트워크/Android/CI/캐릭터 그림은 이 F/G에서 수정하지 않는다. `Game.ts`는 표시 생명주기·읽기 전용 시간·안전영역 측정·메뉴 뒤로 가기만 바뀌므로 Claude가 함께 확인한다.
- 기존 E2E 선택자를 유지한다. HUD 높이 문제는 UI를 고쳤고, 일괄 승급 검사는 기존 `>=3` 기대값을 유지하며 대기만 보완했다. 선택창에는 실제 웨이브 시간을 표시하며 만료·자동 선택·경제 규칙을 추가하지 않았다.
- 서버 없이 작동하는 로컬 글꼴·SVG·기존 WebP와 원본 절차 숲 그림을 사용한다. 참고 게임의 캐릭터·로고·문구를 복제하지 않는다.

새 유료 재화/불꽃 연결, 친구·채팅 서비스, 임의의 선택 만료 규칙, 경제 조정은 이번 UI 범위에 추가하지 않았다.
