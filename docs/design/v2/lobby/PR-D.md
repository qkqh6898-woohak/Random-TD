# V2 PR-D — 메인 로비

검토 전용 `design/v2-pr-d`. 의존 순서는 [PR-B #73](https://github.com/qkqh6898-woohak/Random-TD/pull/73) → [PR-C #74](https://github.com/qkqh6898-woohak/Random-TD/pull/74) → PR-D다. **PR 대상은 `design/v2-pr-c`**로 두어 D 변경만 검토한다. main에는 병합·푸시하지 않는다.

최종 원격 확인에서 PR-A·V2 수정이 main `3abfda6`에 통합된 것을 발견해 B/C 의존 브랜치를 병합으로 갱신했다. 히스토리를 다시 쓰지 않았다. B 갱신 `091d0ef`, C 갱신 `18741cf`. PR-A의 경제·저장·등급 단일 정의·배지 규칙을 보존한다. 이전 `68052a7` 기준의 검사 기록은 최종 통합 결과와 섞지 않는다.

## 이번 단계

- **야영지**: 오리지널 갈색 협곡 SVG, 기존 광부 WebP, 두꺼운 갈색 윤곽선, 로컬 주아체, 노란 입체 시작 버튼. 캐릭터 159장의 그림은 변경하지 않았다.
- **상단**: 광부 아바타·실제 계정 Lv/경험치·기존 골드/보석/불꽃 3개. `원정대`는 일반 라벨이다. K/M은 표시만 축약하며 ARIA group으로 정확한 정수를 읽는다. 축약된 자식은 중복 낭독을 막는다.
- **메뉴**: 오른쪽 위 메뉴 → 기존 기록/설정 창. native dialog의 초점·Escape·Android 뒤로 가기를 유지한다. 메뉴를 닫으면 열었던 버튼으로 초점을 돌리고, 다른 창으로 이동할 때는 그 창의 초점을 유지한다.
- **양옆**: 퀘스트·영웅 모집, 리미티드·카드 상점. 이름은 현재 `GRADE_NAMES.hidden`, 도감 점은 현재 `codexReady`를 쓴다. 지급/레벨업/해방 판정은 기존 ProgressStore와 모델이다.
- **시작부**: 영웅 준비/웨이브 보상 보조 알약, 폭55% 노란 시작 버튼, 새 게임 배속. 웨이브 보상은 받을 보상(없으면 현재 기록)으로 목록을 돌리고 초점을 옮긴다. 저장이 있으면 이어 하기와 새 게임 확인을 유지한다.
- 개발자 캠페인 버튼은 시작 버튼 아래의 배속 줄을 공유한다. 일반/개발자 시작 버튼의 위치가 같다는 기존 검사도 보존한다.
- **탭 5칸**: 상점/영웅/전투/도감/캠페인. 선택 칸은 밝은 면·아이콘1.3배·라벨, 나머지는 아이콘과 접근성 이름. 실제 캠페인 잠금/해금 판정을 유지한다.
- 짧은 화면에서는 중앙 캐릭터 장식/보조 설명을 접고, 620px 이하에서는 레일을 줄여 조작 영역을 확보한다. 기존 무대 비율과 Phaser 캔버스는 유지한다.

**Claude 검토 지점:** Boot/Game은 공유 파일이다. 위 표시 연결만 확인한다. D diff에서 GameContext, sim, save, meta, data, audio, net, update, Android, CI, 캐릭터, package/lockfile은 변경하지 않는다. SIM_VERSION과 저장 형식은 그대로다. PR-A를 덮어쓰지 않도록 3-way 패치의 충돌은 현재 main 동작을 기준으로 해결했다.

### 배속 계약

`LobbyOptions.onStart(speed?)` → `Boot.startGame(mode, initialSpeed = 1)` → `GameSceneData.initialSpeed?` → 기존 `availableSpeeds` 검사 → 기존 TickClock.

- 기본 ×1, ×2→×4→×8→×16→×1 순환. 수치 목록은 기존 `game.json`에서 읽는다.
- 선택은 로비 수명 안의 표시 상태. 새로 열면 ×1이며 저장 키를 추가하지 않는다.
- 이어 하기는 **저장된 speed 우선**. 유효하지 않은 값은 기존처럼 ×1.
- 캠페인/재도전 등 기존 진입은 기본 ×1. 틱/최대 프레임/자동 저장/오디오 예산은 수정하지 않는다.

## 검증

최종 기계 판독 결과: [validation.json](validation.json). 배포/단일 HTML HTTP: [bundles.json](bundles.json). 320·360·393·412px의 로비/메뉴와 320px 이어 하기·눌림·비활성 캡처는 `screens/`. 로비 JSON에는 넘침/잘림/터치/그림/대비를 기록한다. 매우 긴 화면의 기존 레터박스는 그대로다.

- `/usr/bin/chromium`, deviceScaleFactor1. 브라우저 설치 명령을 사용하지 않는다.
- 기본 Chromium의 UI 검사와 지원되는 Canvas 대체 렌더러의 전체 검사를 구분한다. 320px는 `999.9K`/`1.2M`도 검사한다.
- 안전영역은 CSS 변수로 모의한다. 실제 Android 노치·물리 터치·서명 APK 확인은 통합 단계에 남는다.
- 최초 기준의 환경 중단과 오래된 기준의 실패를 최신 main의 통과/실패 수에 합산하지 않는다. 최종 실행의 실패/재검증은 JSON에 명시한다. 기존 기능 테스트를 약하게 바꾸지 않는다.
